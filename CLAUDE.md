# CLAUDE.md — Ledgerleave

Learning project: PTO and approvals for a 50-person company. Two pure engines nothing else in the portfolio has: an **accrual engine** (balances that grow over time under policy rules — tenure tiers, hire-date proration, carryover caps, max-balance caps, three kinds of policy year — derived by replaying an append-only ledger, never stored) and an **approval-routing engine** (ordered approval chains from a routing table, with out-of-office delegation, self-approval rules, HR fallbacks and a frozen chain, every decision carrying ordered reason codes). **Synthetic data only. Never real people. The sick-leave rule is a sample, not legal advice; nothing here is HR, payroll or employment-law guidance.** Keep the scope-honesty banner verbatim in README.md.

Read first: `prd-ledgerleave.md` (what), `docs/decisions.md` (authoritative; outranks the PRD), `docs/domain-brief.md` (vocabulary, C/A/L/R/S rules, policies as data, golden cases GA-01..GA-20 and GR-01..GR-15, measurements, fixture hashes), `docs/portfolio-overlap.md` (what to port, what not to build). Current work: `docs/phase-1-tasks.md`. Session state: `NEXT.md`.

## Non-negotiables
1. **A balance is never stored.** `balance(employee, leaveType, asOf)` is the sum of ledger entries effective on or before `asOf`; `available` is the sum of every posted entry. There is no column, cache or materialized number that product code reads instead. `ledger:verify` recomputes every employee-year from entries and compares it to `fixtures/expected_balances.csv`.
2. **The ledger is append-only.** Accrual, usage, reversal, adjustment, forfeiture and transfer are rows. Cancelling an approved request writes compensating `USAGE_REVERSAL` rows dated like the usage they reverse. UPDATE/DELETE on ledger and request-event tables is rejected by DB triggers (Phase 2).
3. **Both engines are pure and deterministic.** `src/accrual/` and `src/routing/` import no database, clock, randomness, network or model client. Same inputs, same ledger, same chain. Policies and the routing table are JSON data with closed vocabularies; a new vocabulary value needs a `docs/decisions.md` entry and a golden case.
4. **Integers for time.** Hours are integer **minutes**; a work day is 480. The rounding rule is a policy field (`HALF_UP` or `FLOOR`) applied once per accrual event. No float touches a minute.
5. **Dates are strings on a calendar axis.** `YYYY-MM-DD` everywhere; no `new Date(string)`, no `@db.Date`, no process timezone in the engines. CI runs under a non-UTC `TZ` to prove it.
6. **The chain is frozen at submit.** A later org change, delegation or role change does not re-route an in-flight request. An approval by someone who is not the step's approver, is no longer employed, or (for an HR-selected step) no longer holds the HR role is **void** and logged, never applied.
7. **Fixtures are frozen.** `fixtures/` is generated by `tools/build_fixtures.py --seed 20261025` and `tools/reference_leave.py --write-expected`; `tools/verify_fixtures.py` must print OK in CI. Product code never reads `expected_*.csv` or `ledger.csv`; only `leave:eval` and `ledger:verify` do.
8. **Never edit an expected value to pass a test.** GA/GR values and `expected_*.csv` come from the oracle in `tools/`. If TypeScript disagrees, stop and show the owner both derivations.
9. **Numbers, not adjectives.** Screens, commit messages and write-ups say "5057 entries, 389 requests, 0 diffs against the oracle", never "correct" or "robust" without the number.
10. **Nothing leaves.** Approval requests and decisions queue to the notifications outbox as `QUEUED` and are never sent; no email, calendar, payroll or model API is called in Phases 1–3.

## Working rules
- **TDD order:** calendar (C-rules, working days, pay periods, clamped anniversaries) → policy loader and validator → accrual events (A1–A5) → ledger replay and balance (L1–L2) → boundaries and forfeiture (A6–A7) → routing (R1–R9, GR goldens) → state machine (S1–S6) → full simulation and `leave:eval` → (Phase 2) schema, triggers, writes, outbox → (Phase 3) UI. Write the failing test against a committed fixture first.
- **Fixtures:** tests read `fixtures/`; code never generates them. To change a fixture, change `docs/decisions.md` first, regenerate with `tools/build_fixtures.py` then `tools/reference_leave.py --write-expected`, confirm `tools/verify_fixtures.py` and `tools/golden_answers.py` print OK, update the hashes in `docs/domain-brief.md` §12, review the diff.
- `tools/*.py` are test oracles, not product code. Don't port them line for line; `leavelib.py` is the spec made executable, the TypeScript engines are written from `docs/domain-brief.md` §3–§7 and must agree with it on every entry and every chain.
- **Port before you write.** Donors are listed in `docs/portfolio-overlap.md`. Read the donor, port it, record the lineage in `docs/decisions.md`.
- Phase gate: don't start the next phase until the current phase's exit criteria pass. Phases: 1 engines + oracle agreement + eval (no writes) → 2 schema, triggers, writes, outbox, proofs → 3 UI. Write the next phase's task list at the gate and stop for review.
- Adding a policy field, routing code, ledger kind, state or transition needs a `docs/decisions.md` entry and a golden case or fixture.
- Policies, the routing table and holidays are JSON/CSV data, not TypeScript.
- Small commits, one concern each, naming specific files (never `git add -A`). Note seams for non-goals but don't build them.
- **Ask before adding dependencies.** No date library (the calendar module is ~80 lines and the point is to own it), no state-machine library, no CSV library, no scheduler.
- **Model is pinned to Claude Fable 5.1 (`claude-fable-5-1`)** in `.claude/settings.json` (D-3).
- **Built unattended in a cloud session.** Deliver as a branch and a PR; never merge. The sandbox may fail to download Prisma engines or Playwright browsers: say so in `NEXT.md` and let CI decide. CI is the gate, not the local run.
- End each session by updating `NEXT.md`: what was built, decided, left open, and the gate output.

## Stack
TypeScript on a clone of saas-foundation v1.3.0: Next.js 16, Prisma 7, PostgreSQL 17, vitest, Playwright. **Port 6300** (proposed; the first session confirms against the port table in `~/.claude/CLAUDE.md` when that file is reachable, otherwise records "unverified" in `NEXT.md` — D-4). Foundation modules: keep orgs, roles, invites, audit, notifications (outbox); remove or leave unwired billing and share links (D-5). Immutability via triggers as hand-written SQL in Prisma migrations. Python only in `tools/` (stdlib only). Template-owned paths (`src/core/**`, `tests/invariants/**`, core migrations, security routes) are never edited here; `npm run foundation:drift` enforces it. Local `DATABASE_URL`s carry `?connection_limit=10&pool_timeout=20`. `vercel.json` carries the house `ignoreCommand`. CI runs with a non-UTC `TZ`. Public repo `shanelabountyai/ledgerleave`.

## Commands (create in Phase 1, task 1.1)
- `npm test` — vitest against the local `ledgerleave_test` database
- `npm run leave:eval` — replays `fixtures/` through both engines; prints the §11 summary and the per employee-year table (accrued, capped, used, forfeited, balance in minutes) and, with `--requests`, per request (frozen chain, final state); exits non-zero on any diff against `fixtures/ledger.csv`, `expected_balances.csv`, `expected_requests.csv`. Prints `0 entries` and exits 0 until task 1.9
- `npm run ledger:verify` — Phase 1: recomputes every balance from `fixtures/ledger.csv` and compares to `expected_balances.csv`; Phase 2: the same against the database
- `npm run fixtures:check` — `python3 -I tools/verify_fixtures.py && python3 -I tools/golden_answers.py && git diff --exit-code fixtures/ && test -z "$(git status --porcelain fixtures/)"`
- `npm run engine:lint` — schema-validates `fixtures/policies.json` against the closed vocabularies, greps `src/accrual/` and `src/routing/` for `Date.now`, `Math.random`, `prisma`, `fetch`, `anthropic`, `new Date(`
- `npm run leave:route -- --employee <id> --start <d> --end <d> --submit <d>` — Phase 1 CLI: prints the predicted chain with reason codes, writes nothing

## Definition of done (any task)
Tests green, `leave:eval` matching the oracle with 0 diffs, `fixtures:check` OK, `engine:lint` OK, no float minute and no forbidden import under `src/accrual/` or `src/routing/`, decisions doc updated if a rule changed, `NEXT.md` updated, numbers (not adjectives) in the commit message when a measurement changed.
